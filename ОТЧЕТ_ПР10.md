## 4. Административная панель

Модели зарегистрированы декоратором @admin.register. EventAdmin: list_display с вычисляемым столбцом «Активных записей» (annotate() в get_queryset()), list_editable (цена, вместимость), list_filter, search_fields, date_hierarchy, fieldsets, readonly_fields, inline записей. UserAdmin: столбцы, фильтр по категории, поиск, inline записей. PlanAdmin: list_editable статуса, фильтры по статусу и категории мероприятия, поиск по event__name и user__name, list_select_related, autocomplete_fields, массовые действия «Отменить», «Вернуть в активные», «Отметить как посещённые». Названия приложений, моделей и полей – verbose_name, заголовок панели – admin.site.site_header.

## 5. Модели, миграции и менеджеры

Булев признак is_cancelled заменён полем status (TextChoices ACTIVE, CANCELLED, COMPLETED) тремя миграциями: 0002_plan_status (новое поле), 0003_migrate_plan_statuses (RunPython: отменённые → cancelled, остальные → active, есть обратная функция), 0004_remove_plan_is_cancelled. Созданы PlanQuerySet/PlanManager (active(), cancelled(), completed(), for_date(), with_details()) и EventQuerySet (with_seats(), upcoming()). Event получил slug (Unidecode + slugify, миграции заполнения и уникальности), get_absolute_url() и маршрут /events/<slug:slug>/ (старый адрес по id даёт 301), GeneratedField is_family (возраст 6+ и младше, db_persist=True) и help_text у вместимости. Контекстный процессор leisure_context передаёт во все шаблоны название сайта, число мероприятий и константы Plan.Status.

## 6. Проверка ORM-запросов, доступности и статистики

Фильтрация по дате, мероприятию, посетителю и статусу, сортировка по словарю PLAN_SORT_FIELDS и пагинация работают совместно, параметры сохраняются при переходе по страницам. Свободные места считаются только по активным записям (with_seats()): отмена записи через админку или cancel() освобождает место и возвращает мероприятие в подбор. Статистика считает записи по статусам через aggregate(Count("id", filter=Q(...))).

## 7. Анализ SQL-запросов в Django Debug Toolbar

Toolbar подключён только при DEBUG = True (INSTALLED_APPS, middleware, INTERNAL_IPS, debug_toolbar_urls()). Список записей с фильтром и страницей – 5–6 запросов: COUNT(*) для пагинатора, страница записей одним JOIN (annotate(F()) + values()), справочники мероприятий и посетителей, проверка выбранного мероприятия формой, контекстный процессор. Карточка записи – 2 запроса (select_related), статистика – 7. Повторных запросов к связанным объектам (N+1) нет, prefetch_related() не требуется.
