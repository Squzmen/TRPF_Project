# Система планирования культурного досуга

Консольный индивидуальный проект для подбора культурных мероприятий и ведения
плана посещений. Продолжение проекта ПР1: проверки возраста, категории, бюджета,
даты и наличия мест теперь работают с каталогом и несколькими посетителями.

## Возможности ПР2

- Просмотр каталога, поиск по части названия, фильтрация по категории,
  сортировка по цене билета.
- Проверка мероприятия по параметрам посетителя и числу свободных мест.
- Добавление записи в план и отмена по ID; повторная запись того же имени
  на то же событие и превышение вместимости запрещены.
- Просмотр записей и статистики (число мероприятий, записей и сумма цен
  билетов). Коллекции и циклы применены при подсчете, поиске и выводе.
- Сохранение изменений в JSON между запусками, проверка целостности данных
  при загрузке, повтор запроса при ошибочном вводе.

## Структура

| Путь | Назначение |
| --- | --- |
| `main.py` | Меню, ввод и вывод |
| `events.py` | Каталог и проверки, развивающие сценарий ПР1 |
| `plans.py` | Свободные места, добавление, отмена, статистика |
| `storage.py` | Загрузка и сохранение JSON, проверка данных |
| `utils.py` | Безопасный ввод чисел и строк |
| `data/events.json` | Демонстрационный каталог мероприятий |
| `data/plans.json` | Сохраненные записи посетителей |
| `tests/` | Автоматизированные тесты pytest |
| `requirements.txt` | Инструменты тестирования и проверки стиля |

Формат каталога: список объектов с полями `id` (целое), `name`, `category`,
`event_date` (`ГГГГ-ММ-ДД`), `age_limit`, `ticket_price`, `capacity`.
Формат планов: список объектов с полями `id`, `event_id` (ссылка на событие),
`user_name`, `user_age`, `preferred_category`, `budget`. Свободные места
вычисляются как `capacity` минус число записей на это мероприятие.
Начальные данные включают спектакль «Гамлет» из ПР1. События демонстрационные,
их даты фиксированы; после этих дат запись на них недоступна. ID нужен для отмены;
система пока не содержит учётных записей и разграничения доступа.

## Запуск

Требуется Python 3.10 или новее; для работы приложения достаточно стандартной
библиотеки. В папке `TRPF_Project`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Пример: `1` — список; `5` — проверка, `6` — запись (ID `1`, имя `Анна`,
возраст `20`, категория `театр`, бюджет `2000`); `8` — планы, `7` — отмена
по ID записи, `9` — статистика, `0` — выход. Дата компьютера для успешной
записи на «Гамлета» должна быть не позже 17.10.2026.

Данные читаются из каталога `data/` независимо от рабочего каталога запуска.
Не удаляйте JSON-файлы: при их отсутствии или ошибке формата программа
сообщит о проблеме и не перезапишет данные пустыми значениями. Для повторной
демонстрации используйте новый ID посетителя либо отмените созданную запись;
сброс данных вручную возможен заменой содержимого `data/plans.json` на `[]`.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8 .
```

Тесты используют временные JSON-файлы и не меняют данные `data/`.
Классы предметной области и Django запланированы для следующих этапов;
на ПР2 сущности представлены списками и словарями.
