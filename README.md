# Система планирования культурного досуга

Консольный проект ПР1 → ПР2 → ПР3: подбор мероприятий и сохранение записей
посетителей. В ПР3 списки словарей во время работы заменены коллекциями объектов.
Исходные проверки возраста, категории, бюджета, даты и свободных мест сохранены.

## Возможности

Меню позволяет просматривать мероприятия, искать по названию, фильтровать
по категории и сортировать по цене; проверять пригодность мероприятия для
посетителя; добавлять и отменять запись; просматривать историю записей,
посетителей и статистику активных записей. Можно добавить посетителя и новое
мероприятие. Ввод проверяется, ошибки работы с файлами выводятся сообщением.
Отмененная запись остается в истории, но освобождает место; активная повторная
запись человека на то же мероприятие запрещена.

## Объектная модель

| Класс | Данные | Основное поведение |
| --- | --- | --- |
| `Event` | `id`, `name`, `category`, `event_date`, `age_limit`, `ticket_price`, `capacity` | проверка возраста, цены и вместимости, `__str__` |
| `User` | `id`, `name`, `age`, `preferred_category`, `budget` | проверка интереса, `from_data`, `__str__` |
| `Plan` | `id`, ссылки на `Event` и `User`, `is_cancelled` | `cancel`, сериализация, `__str__` |

`Plan` хранит ссылки на два существующих объекта. `cancel()` меняет состояние,
не удаляя объект из коллекции. Условия ПР1 вычисляются по свойствам объектов;
поиск и сортировка коллекций остаются обычными функциями (`events.py`), работа
с файлами — в `storage.py`. `@classmethod` используется для восстановления
пользователя, `@staticmethod` — для проверки вместимости. Случайного
наследования между несвязанными сущностями нет.

## Файлы и данные

```text
TRPF_Project/
├── main.py              # консольное меню
├── models/              # классы Event, User и Plan
├── events.py            # поиск, фильтрация, сортировка и проверки ПР1
├── plans.py             # доступность, создание, отмена и статистика
├── storage.py           # загрузка и сохранение объектов в JSON
├── utils.py             # безопасный ввод
├── data/
│   ├── events.json      # каталог мероприятий
│   ├── users.json       # профили посетителей
│   └── plans.json       # ссылки и состояние записей
├── tests/              # проверки pytest
└── requirements.txt     # pytest и flake8
```

При запуске JSON преобразуется в объекты, при сохранении объекты — в словари.
В `events.json` используются поля `id`, `name`, `category`, `event_date`
(ISO `ГГГГ-ММ-ДД`), `age_limit`, `ticket_price`, `capacity`. В `users.json` —
`id`, `name`, `age`, `preferred_category`, `budget`. Записи в `plans.json`
содержат только `id`, `event_id`, `user_id`, `is_cancelled`. Ссылки
восстанавливаются на конкретные объекты; поврежденный JSON или неизвестный
ID не перезаписываются пустыми данными.

Старые записи ПР2 с `user_name`, `user_age`, `preferred_category`, `budget`
читаются без изменения файлов. При следующем добавлении/отмене записи сначала
сохраняются посетители, затем записи переводятся в новый формат. Не удаляйте
`data/` без резервной копии. Даты демонстрационных событий фиксированы:
после наступления даты можно добавить в меню новое будущее мероприятие.
Имена пользователей пока служат для предотвращения повторов; аутентификации
и разграничения доступа нет.

## Запуск и проверка

Python 3.10+; для самого приложения достаточно стандартной библиотеки.
В каталоге `TRPF_Project`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8 .
```

Пример для даты компьютера до 17.10.2026: действие `6`, ID события `1`,
имя `Анна`, возраст `20`, категория `театр`, бюджет `2000`.
Действие `7` отменяет запись по её ID. Для других дат добавьте в меню событие
с будущей датой. Тесты используют временные JSON-файлы и не меняют `data/`.
